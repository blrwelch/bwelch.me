# Resume / Cover Letter Template

These two scripts are the canonical formatting for Brittany Welch's tailored
resumes and cover letters (Calibri, teal #1A5F7A accents, US Letter, matching
margins/spacing). Every tailored application should be generated by feeding
new *content* into these scripts, not by rewriting the styling from scratch.

## Usage

    node resume_template.js <data.json> <output.docx>
    node cover_letter_template.js <data.json> <output.docx>

Requires the `docx` npm package (already used elsewhere in this workflow).

## resume data.json shape

    {
      "subtitle": "string (header tagline, tailored per role)",
      "summary": ["paragraph", ...],
      "experience": [
        { "title": "", "dates": "", "company": "", "bullets": ["", ...] }
      ],
      "skills": [ { "label": "", "items": "" }, ... ],
      "certifications": ["line", ...] | null,
      "awards": ["line", ...] | null,
      "education": "string",
      "references": [
        { "name": "", "title": "", "relationship": "", "phone": "", "email": "", "linkedin": "" },
        ...
      ] | null
    }

References render as a bulleted list per person (Name, Title, Relationship,
Phone, Email, LinkedIn) — this is Brittany's standard reference format as of
September 2026. The older 2-line shape `{ name, title, detail }` (name/title
on one line, a free-text detail line below) still works for backward
compatibility with anything generated before this format existed, but new
applications should use the fielded shape above.

## cover letter data.json shape

    {
      "date": "September 8, 2026",
      "addressee": "[Hiring Manager Name]" | "Actual Name" | ["line1","line2"],
      "company": "Company Name",
      "salutation": "Dear Company Hiring Team,",
      "paragraphs": ["p1", "p2", "p3", "p4"],
      "closing": "Sincerely,"
    }

After building, convert to PDF with soffice.py (see the docx skill) so both
formats stay in sync, and keep both files under the same base filename as
the rest of the Job Search folder.
